# Content editor: what the client doesn't have

Vanguard's world content lived in SOE's database, not in the client. This file tracks every piece of server-only data we find, so a hosted, crowdsourced **encounter editor** can be built at the end of the project. People will use it to place spawns, draw patrol routes, build encounters and write quests. Everything is saved as shared JSON that anyone can reuse.

Status: a first, local editor exists (2026-10-15): **`python tools/editor.py`**, then open http://127.0.0.1:8099.
- **Files tab:** every content file (`server/content/*.json`, `spawns/<chunk>.json`) edited as JSON. Check runs the validator; Save writes only when the JSON parses and `content.validate()` finds no problem with the change applied (tested on a copy of the folder). The old version goes to `server/backups/content/`.
- **Mobs tab:** a form per mob template: name, title, pawn class, race or creature (all 332 race ids from CREATURES.md), model, gender, level, health, damage, aggro radius, faction, loot table and merchant list as pick lists, role check boxes (trainer, banker, repair, station...), and the remaining fields (gear, abilities, spells, harvest, parley...) as JSON. The model variant field lists the variants the chosen race has (from CREATURES.md) and turns red for one it doesn't. Gear (what humanoid NPCs wear) is edited as rows of mesh type (CHEST, LEG, SWORD... from GEAR.md), mesh number and equip slot: the number field suggests the models that exist in the client's `<TYPE>_ITEMS.uem` and flags a number that doesn't. New, Duplicate and Delete; Save validates the whole file first (deleting a mob that spawns still use is refused).
- **Items tab:** a filterable list and a form per item: type, equip slot, icon, rarity, required level, armor, damage, delay, skill, model (mesh type and number), description, flags (no trade, soulbound, bind on equip...), stats and mods as rows, and the remaining fields as JSON. The pick lists come from the server code (`/api/schema`). The icon number shows the icon itself, and **Pick** opens a grid of all 2,063 client icons (read from `VGUIAssets/Global/Icons/iconsTK.xml` and its TGA/BMP sheets, decoded by the editor); the Loot tab shows each row's icon too. The validator now also checks item types, slots, flags, rarities, stats and mods.
- **Loot tab:** loot tables as rows (item with suggestions from items.json, chance %, quantity min/max, icon filled in from items.json); New table, Add item, Remove. The validator now checks chances (0..1) and quantities.
- **Shops tab:** merchant lists (merchants.json) as rows of item (with icon and suggestions) and price in copper, which NPCs sell each list, and a warning for items missing from items.json.
- **Quests tab:** a form per quest: name, id, level, giver and turn-in NPC (pick lists of mob templates), required quests, greeting, description, summary, accept text, steps as rows (kill a mob, collect an item, talk to an NPC with what they say; count and tracker text), and the reward (experience, coin, title, items, a choice of one, faction changes). New and Delete.
- **Talk tab:** NPC conversations (dialogs.json) as boxes, one per node: what the NPC says, and up to 5 replies, each going to another node (pick list), running an action (wares, faction, give, trade, end) or hidden until a flag. Add, rename (keeps order and fixes every link) and delete nodes, choose the start node, and give any NPC a conversation.
- **Abilities tab:** every class ability in the client (808 rank-I abilities over 15 classes, from the .aby packages) by class, with or without an abilities.json entry. The form covers kind (strike, dot, heal, buff, pet; blank = guessed from the name), icon (with the picker), cast and refresh times, damage, heal, ticks and interval, buff attribute, bonus and duration, maintained stance, description, and other fields as JSON. **Fill this one / Fill all from the archive** add what the archive knows and the entry lacks: the icon (the archive's `IconNNN.png` numbers are the client's icon numbers, checked by eye), the tooltip as description, and cast and refresh times, with the source URL. 355 class abilities have archive data, 200 of them an icon. The server now uses abilities.json's icon, description and refresh in the ability book and the trainer list, not only the effect.
- **Archive tab:** searches the ~19,000 records collected from the community archive (`crowdsourced/raw/*/*.jsonl`: creatures, NPCs, items, quests, loot, merchants, abilities, recipes, zones, diplomacy cards), newest record per name, and shows every known field with its sources, confidence and notes. The Mobs, Items and Quests forms have a "Look up in archive" button. It is a reference for filling in content by hand; nothing is imported automatically. For a creature, NPC or item record, **"Start a new mob/item from this record"** opens a draft in the Mobs or Items form with only the values the archive has (creatures: race from the creature kind, level, health, damage, aggro range; items through `crowdsourced/convert.py`: type, slot, rarity, level, armor, damage, delay, stats and mods, with unmapped fields kept under `_unsupported`), the source URL in `_source`, and a list of what still needs filling in (for example health, or the icon). Nothing is saved until you press Save, and the validator still has to pass.
- **Round-trip self-test:** opening the page with `#selftest` puts every quest and mob through its form and back and reports any change; `test_systems.EditorPageTests` runs it in headless Edge (skipped without Edge). It caught prop meshes (race ids outside the race list) being dropped by the race picker.
- **Spawns tab:** a chunk's terrain from the client's map (shaded heightmap, sharper when zoomed in) with its spawns (red = aggressive, blue = merchants, trainers and bankers, green = others; circles = wander radius). Click a spawn to edit its mob, position, facing, respawn and wander radius, drag it to move it, click empty ground to add one, press Delete to remove it, then Save spawns. Patrols: the loop is drawn on the map; shift-click adds a waypoint to the selected spawn, the pause at each point is a field, Clear patrol removes it, and dragging a spawn moves its patrol along. Obstacles (rocks, walls, trees the server steers NPCs around, from `server/obstacles.py`) are drawn in orange at 16x and closer, and saving warns (without refusing) about a creature standing inside one or a patrol leg crossing one.
- **Live reload:** a running server checks the content files every 5 s and reloads them when they change and still validate. A changed spawn file is also applied to its chunk if players are in it: the chunk's spawned NPCs are closed and created again from the file (seen live 2026-10-15: a Thornback Bear added to the file by hand appeared within seconds; restoring the file removed it; with two clients, the second one saw an NPC added this way too). The in-game builder changes the world itself, so its saves don't trigger this. A changed mobs.json, quests.json, dialogs.json or loot.json (the files NPCs are built from) re-creates the NPCs of every loaded chunk the same way (seen live: renaming the Thestran Guard to "Captain Reyes" changed its name plate within seconds).
- By default it listens on 127.0.0.1 only and has no logins.
- **Login mode (crowdsourcing):** `python tools/editor.py --accounts --host 0.0.0.0 --cert server.crt --key server.key` asks for a game account (server/accounts.py). Contributor accounts (the default) cannot save: Save submits the change as a **proposal** (with a note for the reviewer), after the same validation. Admins (`python server/accounts.py editor <name> admin`) save directly and review proposals in the **Proposals** tab as a coloured diff, with a warning when the file changed since the proposal was made, and Approve (validated, saved with a backup) or Reject. Contributors see their own proposals and their status.
  - Proposals are kept in `server/proposals/` (git-ignored), with who proposed and who reviewed.
  - Safety: failed logins share the server's throttle (5 per address per 5 minutes). Sessions are HttpOnly, SameSite=Strict cookies (Secure over HTTPS) that expire after 12 hours. Every change needs an X-Editor header, which another site's page cannot send. The editor refuses to listen beyond 127.0.0.1 without --accounts, and warns when there is no HTTPS.

Content already loaded from JSON (`server/content.py`; run `python content.py` to validate): `content/mobs.json`, `content/loot.json` and `content/spawns/<chunk>.json`. A spawn's z is optional and comes from the terrain heightmap.

## What the client provides

Verified 2026-10-12 by scanning all 325 maps in `Assets/Maps`.

- **World geometry for every chunk:** terrain heightmaps (`server/terrain.py`), about 54,000 compound objects, 3,900 static meshes, water and lava volumes, lights, fog, weather.
- **Map markers:**
  - 431 `PlayerStart`s. These are not reliable spawns: in `chunk_n19_12` one hangs over a canyon and one is over the sea.
  - 12 `PathNode`s, which look like leftovers.
  - Effect markers that hint at inhabited places: bonfires, chimney smoke, crafting steam.
- **Models:** all character and creature models (332 race ids incl. creatures, with variant numbers: [CREATURES.md](CREATURES.md)), and item meshes (`Assets/Characters/Meshes/<TYPE>_ITEMS.uem`, see [GEAR.md](GEAR.md)).
- **Ability visuals:** for player classes and NPCs (`Assets/Abilities/*.aby`, including `NPC_ABILITIES` and `NPC_BASE_ABILITIES`, see [ABILITY_VISUALS.md](ABILITY_VISUALS.md)).
- **UI and messages:** item icons (`VGUIAssets/Global/Icons/iconsTK.xml`), UI text, and every message layout.

## What the archive scrape could add next (2026-10-15)

Measured with `tools/quest_readiness.py --branch` and the importer after the zone-map imports. In order of what each would unlock:

1. **Quest objective targets** (1,722 objectives): a quest page's objective names something ("Okami Organs", "Tiberian Wildwood Shadowhounds") with no creature or item page yet. Creature and item pages for those names, with a location or a dropper, would make most of the 1,270 quests whose giver is already placed playable.
2. **Creature locations** (175 objectives): the creature page exists but gives no location and no zone-map place names it. A location line ("x, y, z in Zone (cx, cy)") or a map place is enough.
3. **Who drops an item** (92 objectives): the item page exists but no placed creature's loot lists it.
4. **Quest givers with no position** (2,100 quests): neither the NPC page nor the quest page ("location") places the giver.
5. **NPC race and gender** (98% of NPCs): racial cities show the continent's human race.
6. **Merchant wares**: no page lists what a merchant sells; role stocks stand in.
7. **Aggression**: only about 10% of creature pages say "Aggressive" or "Passive". Of the 207 creatures placed so far, 137 are marked Aggressive (and attack first), 8 Passive, 62 unknown (treated as passive).

## Planned editor (end of project)

1. **In-game builder mode.** GM chat commands on our server, with the real client as the 3D editor:
   - `!spawn <template>` places a mob at your feet. **Done (2026-10-15, dev commands):** `!spawn <mob key> [wander radius]` appends the spawn to `content/spawns/<chunk>.json` and opens the NPC for everyone in the chunk at once; `!despawn` removes the targeted spawned NPC from the file and the world (seen live with a Thornback Bear; the file came back byte-for-byte). A second client in the chunk sees a spawned NPC at once (seen live 2026-10-15: Justins saw Bram Oakhollow appear next to Ranger, and vanish again on `!undo`).
   - `!path add`, `!wander <radius>` and `!respawn <seconds>` set movement and respawns. **Done (2026-10-15):** on the targeted spawned NPC, saved to its spawn entry and applied at once; `!path clear` removes the patrol (seen live: Bram Oakhollow walked a two-point patrol set with `!path add`).
   - `!camp`, `!delete`, `!undo` and `!save` manage what you've placed. **Done (2026-10-15):** `!despawn` deletes and every change is saved at once, so there is no `!save`; `!undo` takes back the last builder change (up to 20: the file's previous text and the live NPC), seen live with a spawn, a despawn and two undos. `!spawn` warns when the spot is inside an obstacle.
2. **Web forms** for mob templates, loot tables, items, quests and dialog, plus a chunk map drawn from the heightmap with spawns plotted on it.
3. **Shared JSON in a git repository.** For example `content/spawns/<chunk>.json`, `content/mobs/*.json` and `content/quests/*.json`.
   - Contributions arrive as pull requests, checked by a validation script (model ids exist, positions are on terrain, levels are sane).
   - The content gets a data license (for example CC-BY-SA), separate from the code's AGPL.
4. **Importers.** Scripts that turn old fan wiki and guide data (and VGOEmu data, if they share it) into draft JSON for builders to verify in game.
5. **Player feedback in game.** `/bug` opens the client's Bug Report window. Submit sends 0x4aa {wstr description, i32 category, i32 severity, i32 reproducibility}, and the server stores it in `server/bug_reports.json` (not committed) with the player, chunk, position and target (`server/bugs.py`). The editor can show these reports on the chunk map next to the spawns. The client also has a Quest Report window (0x4ad opens it; ratings for challenge, rewards, lore, confusion and fun). It is not wired up yet.

**Bard songs:** the song parts (melodies, verses, embellishments, bridges, lyrics, choruses, codas, rests), with each part's effect and energy cost, were server data. `server/content/songs.json` holds placeholders; see docs/SONGS.md.

**Finding spawns in game:** `!npclist [radius]` (dev commands) prints the NPCs near you with the client's GM NPC list (0x786): "Hollis Grent (Lvl 20) camp_banker EncounterDBId: 13 Loc: -31400.0, -5600.0, 450.0." The EncounterDBId is the entry's index in `content/spawns/<chunk>.json` and the tag is its mob key, so a builder can go from what they see in game to the line to edit.

**Quest feedback:** with `--quest-feedback`, the server opens the client's Quest Feedback window (`SGOUI toggle "Quest Feedback"`) after each completed quest. The window asks for challenge, reward, lore, confusion, friends needed, a fun grade and comments. Accept sends 0x4ab {i32 quest id (-1 here), wstr comments, 6 x i32}, and the server saves the answers with the quest key in `server/quest_feedback.json` (not committed). The client's own opener, 0x4ad {wstr, i32}, shows nothing (verified live).

**Loot tables from the archive:** an archive loot record ("Start a new loot table from this record") becomes a loot.json table named after the creature: one row per drop with the chance (the archive's percentage) and the icon from items.json when we have the item. Drops whose item we don't have yet, drops with no chance, and chances observed over fewer than 20 kills are listed for review. Checked in headless Edge with Harbinger of Vilonis (one drop at 33.3%, observed 1 in 3).

**Archive quests (2026-10-15):** `python tools/quest_readiness.py --branch` sorts the archive's 4,774 quests: a quest is ready when its giver is placed in its zone and every objective can be done there (a kill objective like "Timber Wolves Slain (12)" names a creature placed in that zone, singular or plural; a collect objective like "Sprite Essence (0/8)" is in the loot of a creature placed there). `--apply` adds ready quests to quests.json as `arch_<name>` (ids from 5100, never overwriting), starting from the editor's quest draft; the archive has no dialogue for most, so greeting, description and summary are placeholders and XP is 100 per level. Coin comes from the archive only when it has a unit ("1s 40c"); bare numbers ("17") are listed in `_needs`. Quests whose objective is the giver itself (reading a book) are left out. First run: 17 ready (Afrit, Beranid Hills, Nusibe Necropolis, Tursh Village), 21 after the creature camps (two kill quests among them: Foraging from the Sand in Khal, The Discord Of Kaon in Leth Nurae); 1,196 have a placed giver but an objective's creature or item is not placed yet, 2,406 have no placed giver and 1,155 no recorded objectives. Of the objectives blocking the 1,196: 1,722 name something the archive has no creature or item page for yet (the scrape is about a fifth done), 175 a creature the archive knows but doesn't locate, 92 an item whose dropper isn't placed. The editor's "Archive quests" tab shows the same per zone: the ready quests, and for each blocked one the objectives that can't be done yet and why (`/api/readiness`, `quest_readiness.report`). Seen live: Inquisitor Nalstom in Tursh Village offers Rift Gem (star icon), with its objective and 40 copper reward on the quest page.

**Placing a zone's NPCs from the archive (2026-10-15):** the archive's NPC locations ("-9686, -35413, 1540") are the zone chunk's own x, y, z, the same frame as the spawn files, and the client's `bin/Resources/Texts/ChunkNames.txt` names every chunk (Khal = chunk -13, -9; `PoINames.txt` has the map labels in the same frame). Of 305 NPCs with positions in mapped zones, 254 matched the terrain height as (x, y), most of the rest stand on buildings. Checked in game: Afshin Budjiri, a trainer in Khal, stood on the floor of a hall with weapon racks. The scrape publishes to the `crowdsourced/archive-collection` branch; `--raw <folder>` adds another raw folder, e.g. the branch's taken with `git archive origin/crowdsourced/archive-collection crowdsourced/raw | tar -x -C <tmp>`, without merging the branch. `python tools/import_zone.py --all --branch --apply --skip "Sundering Wastelands" --skip "Wildgrowth Forest"` refreshes everything from the branch's newest pages in one go. `python tools/refresh_archive.py --apply` does that, adds the archive quests that became playable and checks the content. `python tools/import_zone.py "<zone>"` writes drafts (crowdsourced/drafts, not committed); `--apply` adds each NPC as a mobs.json template `arch_<name>` (name, level, services as the title, a placeholder race from the continent: Thestra 14, Qalia 13, Kojan 12, and placeholder health) and a spawn at its position, never overwriting, and logs the import in crowdsourced/imported.md. Services the server can run are set too: banker, repair, broker, and trainer with `trainer_classes` from the archive (titles like "Warrior Trainer"); merchants get a placeholder stock: the archive records no wares, so a merchant whose title names a role (weapons, ranged weapons, heavy, medium or light armor) gets a role stock `archive_<role>` of up to 12 archive items of that kind (mundane or common, with a slot, not player-crafted and not named loot such as "Basnaret's Robe" or "Bow of Fighting", spread over the levels, 25 copper per level; `import_zone.stock_merchants`, 35 merchants), the rest the shared `general_goods` (a builder replaces either). Archive items have no icons, so they get one by slot (`import_zone.SLOT_ICONS`: helm, chest, bracer, ...; weapons by name: staff, mace, dagger), else a sack; icon 443, the old placeholder, is a red "prohibited" sign, and loot rows without an icon now fall back to the item's icon, then a sack (`content.roll_loot`). **Quests from the archive:** an archive quest record has a "Start a new quest from this record" button. The draft copies the name, level, steps (collect steps with their item and count; kill steps when a mob with that name exists), rewards (XP, coin, items, choice) and the greeting / description / summary when the archive has them. The giver, turn-in and previous quest become our keys when a mob or quest with that exact name exists; otherwise the archive's names are kept as `_giver_name`, `_turn_in_name`, `_previous_name` and the editor lists what to fill in. Checked in headless Edge with "Got My Eye On Something" (Agent Zyrax, level 15, Reaper's Eye, 3618 XP, four pendants to choose from).

**Work orders in the editor:** the Work orders tab edits workorders.json: id, name, icon, task master, recipe (flagging NPCs that are not task masters and recipes that are not work-order only), difficulty, skill, supplies, deliveries and the reward (coin, crafting XP, faction standing).

**AA and housing plots in the editor:** the AA tab edits aa.json (one row per AA ability: list, title, description, ranks, cost per rank, level, stats, requirements, classes) and the Housing plots tab edits plots.json (each plot's name, chunk, location, cost and upkeep, and its buildings: type, name, prefab, fixtures, chests, construction materials and NPCs). Both are in the page selftest. With these every content file has a form; the Files tab still edits any file as JSON.

**Reactions in the editor:** the Reactions tab edits chains.json (opener, steps, finisher, window per class) and counters.json / rescues.json (ability names per class) and saves all three; in the page selftest.

**Titles, hints and outposts in the editor:** the "Titles, hints, outposts" tab edits those three small files as tables (a column per field; checkboxes for true/false, comma lists for positions). All three are in the page selftest.

**Forms and songs in the editor:** the "Forms & songs" tab edits forms.json (combat forms / mindsets) and songs.json (bard song parts) as one table per file: class, name and a column for every field the file uses (numbers stay numbers, lists are comma separated). A field no entry has yet (for example a form's `abilities`) is added in the Files tab. Both files are in the page selftest.

**Riftways in the editor:** the Riftways tab edits riftways.json as a table (name, region, price color, and the landing chunk and position; an empty chunk means not open on this server yet). It is part of the page selftest.

**Factions in the editor:** the Factions tab edits factions.json as a table (name, starting standing, kill change, allies, enemies, prestige) and shows how many mobs belong to each.

**Crafting recipes in the editor:** the Recipes tab edits recipes.json: id, name, output, icon, XP, max action points, book group, trainer cost, skill, kind, work-order flag, inputs, and the stages with their steps (action, AP, tool, utility item); the catalyst and complications are edited as JSON.

**Diplomacy in the editor:** the Parley tab edits diplomacy.json: the cards (expression, push, cost and gain per expression, refresh), the starting deck and strategy slots, and each parley (option text, type, presence, win/lose thresholds, the NPC's cards, starting pools and replies, and the reward as JSON), with the NPCs that use it.

**Combat forms and Psionicist mindsets:** which forms each class has, and what each one does, were server data. `server/content/forms.json` holds placeholders; see docs/FORMS.md.

**Brotherhood XP bonus:** the real bonus rate was server data; ours is 5% per grouped brotherhood member (`brotherhood.BONUS_PER_MEMBER`).

**Civic diplomacy:** the real civic stats per area, their ranges and their effects were server data; ours is one placeholder value ("Thestran Wastes Camp Prosperity", +5 per win against Orin).

**Deconstruction:** what each item broke down into (components, the level needed) was server data. items.json `salvage` lists the results per item (placeholders on Rusted Dagger and Hunter's Shortsword; default 1 Copper Ingot, or Shimmering Dust); see docs/INVENTORY.md "Deconstruction".

**Alternate advancement:** the AA abilities (general, archetype, class and special lists), their costs, ranks and effects were server data, sent as MsgAlternateAdvancementAbilitiesAdd. `/aalist` (0x85c) and the AA window get no answer until that data exists. Placeholders now: `server/content/aa.json` (9 abilities over the four lists, attribute bonuses per rank) and the AA experience rate in `server/aa.py`.

**Summoned pets:** what each class summon (Awaken Abomination, Summon Attendant of Hayatet/Rakurr/Tuurgin, Ritual Animatus) creates, its race, model, level, health and abilities were server data; abilities.json has placeholders.
